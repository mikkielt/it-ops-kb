# Code: the rules for the tooling in `_tools/`

The Python under `_tools/` follows these rules; a change to it keeps them. They describe what the code does now. Each rule lives here once: the gate and the definition of done (`kb/_self/maintaining.md`, Conduct for changes; `kb/_self/backlog.md`, Definition of done) point here for the code, and `kb/_self/tools.md` lists the tools and their commands.

## Runtime

- **Standard library only.** A tool runs with the interpreter alone, on Python 3.11 or newer, with no install step. `pyproject.toml` names dependencies for development only (pytest, pytest-xdist, ruff); no tool imports them outside a test.
- **The one place a package is installed is `otel/`.** The optional OpenTelemetry adapter `otel/kbmon_otel.py` (a module beside it for each signal: `otel/otel_logs.py`, `otel/otel_spans.py`, `otel/otel_prom.py`) has its own `otel/pyproject.toml` and `otel/uv.lock` and runs as `uv run --frozen --project otel python otel/kbmon_otel.py`; no file in `_tools/` imports an OpenTelemetry package, and the adapter reaches the tools by running them as child processes (`kb/_self/monitoring.md`, The OpenTelemetry adapter).
- **One entry point.** A hook reaches a script through `_tools/kbpy`, never by naming an interpreter (`kb/_self/querylog.md`, Portability).

## Portability

The same code runs on Linux, macOS and Windows.

- **Text is UTF-8.** Every `open`, `read_text` and `write_text` names `encoding="utf-8"`; a write adds `newline="\n"`, so a file has the same bytes on every host. A script that reads or prints text through a pipe (a hook, the MCP server) reconfigures its streams to UTF-8.
- **Paths go through `pathlib`** in new and changed code (older modules still use `os.path`): no string joins with `/` or `\`, no shell syntax in a path. A path written into a doc or a ledger uses `/`.
- **Subprocesses take an argument list**, never a string and never `shell=True`. A tool starts Python with `sys.executable`, not `python3`, which on Windows can be a Store alias.
- **A file at a revision is read with `git cat-file blob REV:PATH`**, never `git show REV:PATH`: `show` also checks its argument as a file name, which fails as "Filename too long" in a deep Windows checkout.
- **No Unix-only calls** (`fcntl`, signalling a PID to probe it, `os.fork`). A lock is an `O_EXCL` file; a detached child sets the creation flags of each OS.
- **Windows names no process's working directory.** Before removing or moving a directory a process may hold there, a tool renames it to a sibling and back (`bl_close.held_by_process`, with `os.rename`): Windows refuses while a process runs with it as its current directory or holds a file open in it, so a refused rename is a reason to leave the directory as it is.
- **A test skips what a host lacks** (no `sh`, no `git`, no PowerShell) with a marker that names the missing part; it never passes without running.

## Git in tests

- **A test never acts on the real repository.** `_tools/conftest.py` removes the variables that name a repository (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and the others) from the environment before any test, because a git hook sets them and a run it starts would inherit them. It clears `KB_NO_PUBLISH_HOOK` the same way (at import, so in every xdist worker), because a session may export it and a test that needs it sets it itself with `monkeypatch`.
- **A test over the repository's live data holds at any size of it.** A test that reads the live kb or backlog asserts named content or a shape (a verdict, a header, an exit code), never a count or a length another session's growth can break, or it runs over a fixture.
- **A scenario builds its own repository** in a temporary directory, with `git_env()` for its environment: no global or system git config (its own entries only: no automatic maintenance, and `core.longpaths`, since a worktree of a seeded clone under a Windows pytest temp directory passes 260 characters and no host setting reaches the scenario's git, BG-6sdkqlsu), a fixed author and committer, and none of the variables that leak a CI run or a verification date. The `Repo` helper runs git in such a directory, `kb_seed` seeds it with the tool files and kb content a run needs (repacked into one pack, so a scenario's two clones link one file, not one per object), and `scenario` is the fixture that hands a test such a repository. A test that needs git carries the `git` marker, so `tests.py -m "not git"` leaves it out. `tests.py` hands its workers the tests in small consecutive chunks (pytest-xdist `--dist load`, with `conftest.py`'s `SLOW_FIRST` files first; a worker's first chunk is at least two tests and the chunks shrink as the queue drains [kb/public/python/pytest-xdist.md:88-90]), so a file or class is split only at chunk boundaries and is not kept on one worker: two long scenarios of one file can run on two workers, and a module or class fixture is built once on each worker that runs one of its tests.
- **A sync or pre-push run inside a scenario sets `KB_SYNC_NO_TESTS=1`**, so the scenario's own gate does not start the suite again.

## Output

- **Output is deterministic.** The same inputs give the same bytes: sorted iteration where order is not data, `\n` line endings, no BOM, and a clock or an environment value only where recording it is the tool's purpose.
- **Threads leave the output as one worker's would.** A tool that runs subprocesses in parallel uses `concurrent.futures` threads and no extra dependency, writes what the runs return in the order of its input on the calling thread (never in the order they finish), and guards a counter the threads share with a lock (`bench_pool.run_tasks`, `bench_core.SPEND_LOCK`). A read that must not hold the process runs in a daemon thread the caller waits for up to a timeout and then leaves behind (`mon_base.run_panels`): a `ThreadPoolExecutor` worker is joined at interpreter exit, so it would hold the process until the slow read ended.
- **Derived state converges.** A second run on unchanged inputs writes nothing and changes nothing (`build_index.py` twice, `querylog.py learn` and `apply` twice, `kbid.py add` with the same row, `benchmarks.py pool build` and `pool build --querylog` over their own files, which keep the sample they hold (the public one its checks too) and ask no model; a public build asks the model only with `--ask` or `--redo ID` (eval rows the file lacks, or named to ask for again), and with neither lists the rows it would ask, writes nothing and exits 1). A `--check` form writes nothing and exits 1 when a run would change a file.
- **A derived cache's key holds the form of its rule.** A cache of results one of our rules computed (a projection, a leak scan's verdicts or values) puts a form constant of that rule in its key or file name (`kbpublic.PROJECTION_FORM`, `SCAN_FORM`), bumped whenever the rule changes what it yields, so no result cached under an older rule is read (the leak scan's key also holds a digest of the rule's data, `kbcommon.SECRETS` and the registry's private patterns, which no one bumps by hand); a cache of verbatim fetched text needs none.
- **A file another process reads while a run writes it** (the query log's) is written whole or not at all: to a temporary name, then replaced.

## Exit codes

- **Each tool documents its own codes** in its docstring and in `kb/_self/tools.md`; a change to them changes both. A code is never renumbered.
- **The pattern the tools share:** 0 done or nothing to do; 1 the tool found what it looks for (a failed check, stale docs, a change `--check` would make, a failed step); 2 it could not do what was asked (bad arguments, not a git clone, an unreadable input, a refusal); 3 a human or another process must act first (a conflict, a held lock). A tool states where it differs.
- **A hook that only logs or informs exits 0 whatever happens**, so it never blocks a prompt or a tool call by failing; only a gate blocks, with exit 1. A hook that answers by running another tool (`backlog:` runs `backlog.py`) lets the prompt through with a note when that tool fails or times out.
- **A usage error is not a finding.** An argument error exits 2, so a caller cannot mistake it for exit 1.

## Checks and their tests

- **The suite is small and has a ceiling.** `python3 _tools/tests.py` runs the whole suite (pytest and pytest-xdist through uv). `_tools/tests_ceiling.json` holds the most test ids (`max_ids`) and test files (`max_files`) the suite may have and the longest a full run may take per platform (`max_seconds`), with `decision`, the id of the decision that records them. `tests.py` checks the file count and that `decision` names an active decision of `kb/_self/_decisions.csv`, made by the operator, whose text holds the file's own numbers; a full run also fails when it ran more ids than `max_ids` or took longer than `max_seconds`; `tests.py --ceiling` checks ids and files without running a test. On a CI runner `KB_TEST_TIMEOUT_FACTOR` multiplies the seconds, and so does the clone's profile: `usual`, or `busy` for a host that is loaded for good, which multiplies each platform's `max_seconds` by 15 in that clone only; the profile is `profile` in `_private/host.json` (never committed), set by `tests.py --set-profile usual|busy` from the operator's own terminal and refused in an agent session as a ceiling answer is, read by `tests.py`, `perfcheck.py time` and the kbmon host panel (`tests.read_profile`), and named in a refusal; the ceiling file and its decision stay as they are. A number of the ceiling changes only with the operator's recorded answer (`python3 _tools/backlog.py answer ID GATE --answer "tests-ceiling ids=N files=N seconds=..." --by operator --record`, then that decision's id in the file); an agent never raises it, and a full run refused over `max_seconds` on a loaded host is run again once the host is quiet or recorded as a host finding, never answered by a higher number (`kb/_self/backlog.md`, Sprints). A new test id needs room under `max_ids`; at the ceiling it replaces one.
- **A change gets no test by default.** Unneeded tests slow development, and the project prefers fast development and user feedback to test suites that run for hours. A bug is fixed and proven by its `repro` and by user feedback, not a test; what let it through goes into the sprint's retrospective as a process finding, a backlog story when a change is accepted. A planner who finds the suite slow prefers deleting or merging tests to speeding them up.
- **A test exists only for a critical component.** The critical kinds are: a leak or untrusted-code guard (a secret, a private name or an untrusted file must not get through); the push and publish gates, with the query log never reaching the public home; operator-only authority (the gate classes, the ceiling class, the agent-session guard); a format another tool parses. One planted failure per such gate, the input the gate must refuse (a check that no planted input can fail proves nothing, `kb/_self/backlog.md`, Definition of done). A worker adds no test for a component that is not critical, and an existing test of one may be deleted.
- **A test is never** a matrix (at most two `parametrize` cases); a test that reads a doc, a skill or an agent file to assert its wording; a test of a helper when the command's behaviour shows the same; a regression test for a defect a log or user feedback shows.
- **`multi fitness` is the comprehensive check of concurrent work.** Under the test policy (D-6kei5o2z, D-2tq4fhgs) the end-to-end check of agents working at once is not a tests.py test: `python3 _tools/benchmarks.py multi fitness [--dir DIR] [--case NAME]...`, run by the harness, replays the scenarios `lookups`, `research`, `mixed` and `coord` with scripted agents (no model, no network) at once and one at a time and with each `--plant`, and with `--bare` clean and with `--plant bare-leak`, reads each run with `multi check` and exits 0 only when `multi check` passes every clean replay and names every planted fault, and the cases `research`/`coord` under `shared` and `isolated` also hold the deduplication and structured-coordination measures their line prints; `multi record` writes the number of problems `multi check` names about a finished run as the metric `check_failures`. It counts nothing against the ceiling above.
- **Operational errors come from logs, not tests.** They are detected from the ops rows `test.run`, `sync.gate`, `land.step`, `done.refused`, `ci.pipeline` and `python3 _tools/querylog.py digest`, and from a gate's own output. When something breaks later, file a bug and a retrospective finding; the suite does not grow.
- **A compile warning is an error.** Before pytest, every `tests.py` run (a selection and a `--changed` run too, not `--ceiling` or `--write-lint-baseline`) compiles each `_tools/*.py` from its source text, writing no `.pyc`, and exits 1 naming each file and line whose compile warns, such as an invalid escape sequence (a `SyntaxWarning`; a `DeprecationWarning` before Python 3.12): a regex or Windows path in a plain string literal needs a raw string or a doubled backslash. pytest only prints such a warning, a cached `.pyc` does not repeat it, and a file no test imports is never compiled by a test.
- **A file format is named in `kbcommon` and checked in `check.py`.** The decision files (`kbcommon.DECISION_COLS`, `MAKER_COLS`, `POLICY_ROW`, `DECISION_ID`, `context_refs`) are checked by `check.py`'s `check_decisions`, which reports each broken rule by file and line. A remote root's pointer file `kb/_roots/<name>.md` is the same: `kbcommon.pointer_problems` names its rules, `kbcommon.roots()` and `missing_roots()` read it without raising, and `check.py` reports what it flags as a defect.
- **A path limit is a named constant of `check.py`.** `WINDOWS_MAX_PATH` less the length of a typical Windows worker worktree prefix (`WORKTREE_PREFIX`) gives `TRACKED_PATH_MAX`, the longest path `git ls-files` may list; `check.py` without `--root` refuses a longer one. A tool that writes a tracked file under a new directory depth keeps within it.

## Imports

- **A module imports the modules below it.** The facade imports its helpers; a helper never imports its facade. Inside a prefix, the shared ground (`bl_base.py`, `ql_base.py`, `kg_base.py`, `bench_core.py`, `mon_base.py`) imports no sibling, and a stage imports the stages it builds on, never one that builds on it.
- **`kbfacts` is the ground and the facade of its stages.** The `kf_` stages import the ground by name from `kbfacts` while it loads, because `kbfacts.py` imports them last, after every ground name exists; they build on each other in the order `kf_fresh`, `kf_index`, `kf_route`, and `kf_fresh` reaches `kf_route` (`pack_many`) inside the function. `kf_fresh` also imports `kbfacts` itself, to read `pack_store` through it. Nothing imports a `kf_` module first: the stages are loaded by `kbfacts`.
- **No cycles at the top level.** A reach back up the order is an import inside the function that needs it.
- **A leading underscore means the module's own.** Another module does not import or call a name that starts with `_`; a name two modules need is public, without the underscore.
- **A reader of a file format that a writing tool also reads is below it.** `kbdecide.py` imports `kbfacts.py` (to find facts), so the lookup side reads `_decisions.csv` itself, tolerantly and by its columns (`kbfacts.decision_rows`), never through `kbdecide.py`; `check.py` stays the one place that judges the format.
## Writing a checked file

- **A tool that writes a file `check.py` checks asks `check.py` whether the write is clean.** `kbdecide.py` writes a root's `_decisions.csv` (or kb/_self's), then runs `check.check_decisions` over the files as they are and undoes the write, with exit 2 and the errors, when it added one the file did not have before; it never hand-copies a rule of the format, so a row it writes cannot fail the check, and a later rule applies to it at once. The module takes the check as a library, which is the one place a tool imports `check.py`.
- **A refusal exits 2 and leaves every decision file as it was.** The message names the rule. `ratify` and `revert` of an autopilot decision refuse any `--by` but `operator`, a decision that is not an active autopilot one and an empty `--why`, and a revert files its story through `backlog.py`. The commands an agent may not run are `supersede` and `restore` without `--by operator`, and `invalidate` of a `proposed` row, which names no maker. `sweep` is open to agents and applies a rule for each of these: a dropped item, an item deleted at close whose last version in git history is dropped, an item deleted by `drop` outside a sprint whose last version is not done, a superseded source, a gone article or domain, a passed `review_by`; it leaves alone a done item, an item deleted as done, an item still present and a missing fact. The relink flag for a missing fact and `relink`, which is open to agents too, draw on the likeliest fact's sources (git history, anchors, doc2query questions, the decision's words) and offer none below a cut. The tool reuses `kbfacts.fact_key` for a fact's key and `kbfacts.units` for the facts, so it never hashes a fact itself.
