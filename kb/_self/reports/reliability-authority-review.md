# Reliability, authority and cost review

A read-only review of CI reliability, coordination, authority boundaries, redaction, observability and backlog growth, made on 2026-10-27 against `origin/main` 5dff1e085c. Six headless Sonnet sessions (one per workstream: CI and tests, coordination and benchmark economics, authority and destructive operations, redaction and information flow, observability and backlog growth, external standards) each read one detached worktree of that commit, ran only reads, local probes on synthetic strings and one `tests.py --durations 25`, and wrote a report; a lead session assigned the work through coord (a claim on the research key, an ask to `any`, asks between workers), checked the material claims named "verified by the lead" below against the code and the CI log, and wrote this record. Cost of the workers: $23.47 in all (`modelUsage`: Sonnet, plus a little CLI-internal Haiku in two). No commit, push, gate answer, backlog write, branch deletion or paid benchmark was made. The six workstream reports stay local in `_private/research-2026-10-27/` (never committed); every material claim below carries its own `path:line`, run id or record so it can be re-checked without them.

Classes used: **observed** (read in code, a log or a command's output), **verified** (reproduced or cross-checked), **inferred**, **planned** (an item or doc says it will be), **unknown**. Web sources were read on 2026-10-27.

## 1. Executive summary

- **No defect blocks safe single-user operation today.** Git is the arbiter of accepted state and it holds: pushes are compare-and-swap, landings take a lock, publish refuses on any leak or a CI verdict other than `ok`, query-log redaction drops on doubt. The coordination store is a correct lease and event store (every write one `BEGIN IMMEDIATE`, stale tokens refused).
- **The public CI signal is void.** 72 of the last 100 GitHub `kb` runs on `main` failed, and every failed log read (24 of 24 newest) passed every assertion and failed only on `tests.py: over the ceiling ... 60 s on linux`. The 60 s Linux number was never measured on that runner: its median was already 59.9 s at 25 test ids. Darwin cannot see suite growth at all, because with 12 workers its wall time equals the longest single test. A real failure on `main` is now indistinguishable from the standing red, and the `check-trailers` step behind it is skipped on every such run.
- **Three signals say more than they know:** "operator" on a gate answer is a string an agent session may pass for the push, secrets and agents-rule classes; kbmon calls healthy headless sessions orphans and landed items "in landing"; the commit and publish leak gate sees 3 of 21 secret forms that the query-log redactor catches.
- **Authority beyond the OS user is convention.** Every session holds the ambient Owner-level forge credential; Bash deny rules match text, not programs (Claude Code docs); a backlog item's check may run inline Python. That is acceptable for one operator on one laptop and is the first thing to change before shared team roots or a non-loopback coord server.
- **Two generators run without a cap:** sprint reviews and closes park drafts (729 open, all drafts, 90% parked, about +120 to +250 a week), and merged `code/*` branches accumulate on the integration remote (1379, all merged, all protected by a `code/*` wildcard, about 55 a day).
- **Concurrency buys wall clock, rarely dollars.** Lookups: wall /5.8 for x1.18 cost. Same-article concurrent research: x2 cost for 1.3 to 1.5x speed, from rebase contention, not coordination. The model is the largest cost lever. The benchmark's "coordination win" measures a claim step production never runs.
- **Recommended next decision:** the Linux CI time verdict (section 8, choice 1), together with the workflow-only diagnostics that need no decision (sprint item 1). Everything else in the proposed sprint is small, independently landable and mostly without new test ids.

### Outcomes of the two authority experiments (2026-10-27)

- **Experiment 1 (inline check under `done`), outcome: run.** In a throwaway git root (a scratch directory outside the clone, its own `backlog.json`, one story in `doing` with a commit that changes a file the story touches), a planted check `python3 -c` ran `glab auth status` through `subprocess`. `backlog.py done` accepted it (exit 0) and ran it as the operator's own user. So a check reaches the keyring-held forge login and the network-capable CLI; the isolation `run_check` adds is the query-log home, not credentials. Only the logged-in state was read; no token value was kept and nothing was pushed or called beyond `auth status`. This confirms AU-2: the program allowlist stops a check from naming `glab` as its program, not from running it inside Python.
- **Experiment 2 (one headless worker on a Developer-role token), outcome: not run; no Developer-role token file was provided.** The run needs a token file made for that one worker, and none exists.
