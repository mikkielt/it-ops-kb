# Content rules

What a fact, an article, a source row and a ledger entry look like, and how to add them. This file is authoritative; `check.py`, `build_index.py`, the kb-verify lint and `tests.py` enforce most of it.

## Roots

- Knowledge lives in roots under `kb/`: `kb/public/` (the upstream facts) and any root a team adds beside it with `/kb-add-root` (its systems, repositories and runbooks). A root is a directory with a `_root.md` (front matter `root`, `id_prefix`, `visibility`, `description`) and the layout below; every path inside it is relative to the root. `check.py` rejects a malformed `_root.md` and two roots sharing a name or prefix.
- **Ids.** A root's sources get ids with its prefix: public keeps `S` (legacy `S123` and hash `S-k3f7q2zd`), another root `<P>-<8 characters>`, both from `python3 _tools/kbid.py add <URL> ... --root <name>` (Ids, below). A root cites only its own sources (`check.py` errors on a citation of another root's id): when a team's fact rests on a public source, add the url to the team root under its own prefix.
- **Visibility.** `public` roots follow the placeholders rule below and the leak tests scan them; `internal` roots may name real hosts, tenants and people, and stay out of the upstream remotes.

## Layout

- `<domain>/<topic>.md` is one topic. Its front matter has `topic` (equal to the path without `.md`), `priority` (P0-P3: the research order it was gathered in, not importance), `applies_to`, `retrieved_utc`, `sources` and `status`, and optionally `files`. Its body has four sections: Summary, Facts, Reference and Examples. Large tables sit beside it as `.csv` or `.yaml`.
- A topic's files are the `.md` plus sibling files sharing its stem (`auth/flows.csv`), plus any extras in `files: [dsc/cli/, graph/csdl/device.v1.0.xml]` (root-relative paths, directories end in `/`). An article named in another article's `files:` (an artifact digest) is part of that topic. A topic with no `.md` (a CSV-only table) is a row of `kb/public/_retrieval/index_extra.csv` (`topic,priority,status,files`).
- `_sources.csv`: every source, `id,url,title,publisher,licence,reuse,retrieved_utc,version_or_date,artifact_sha256,used_in,superseded_by`. `licence` names the terms and where they are stated; `reuse` is their class (Licensing, below). A new row is written by `python3 _tools/kbid.py add` (Ids, below). `used_in` is generated (the domain files that cite the id). `superseded_by` is empty unless a newer row replaced this one; it then names that row's id.
- `_artifacts.csv`: every pinned structured artifact (JSON schemas, DSC manifests, Graph CSDL, the MCP `schema.ts`, the A2A `.proto`, baseline exports, semantic-convention registries), with its sha256 and a Markdown digest beside it.
- `_answers.md` (research answers with evidence), `_gaps.md` (what could not be confirmed and where it was looked for), `_conflicts.md` (where sources disagree, both sides linked).
- Generated, never edited by hand: `_coverage.csv`, the table in each root's `_coverage.md`, `n_sources` and `used_in`. After any content change run `python3 _tools/build_index.py` (CI runs `--check`). Rows are ordered by domain, priority, topic id.
- `_census/<date>.csv`: a census verdict log, one row per source with its mechanical bucket (OK, CHANGED, GONE, NEWER-VERSION, NEEDS-READING), the evidence and what reading decided. `_fetch_state.csv`: per source, when `fetch.py --diff` last checked and fetched it, when it last changed, and the hashes compared; snapshots of the last fetch sit in `_cache/snapshots/` (never committed). Search skips both.
- `_anchors.csv` (`_tools/factdiff.py`): per fact and cited source, where the fact's backing passage sits in the source: the heading path (a ranking hint only), the fact's key terms, a hash of the normalized passage, a quote of at most 25 words when the source's `reuse` is `copy` or `quote` (never one that looks like an address, a home path or a token), and when it was last found; or `unlocated:<reason>` when no passage holds the fact (listed, never guessed). A reworded fact gets a new key: `python3 _tools/factdiff.py anchor --file <path>` re-anchors it. `check.py` enforces the format; generated, never edited by hand.

## Facts and tags

- Every fact ends in exactly one tag with ids from `_sources.csv`: `DOC` (an official document states it), `CODE` (source code states it, read at a pinned commit), `DER` (derived from DOC or CODE facts, derivation shown), `COMMUNITY` (a non-official source; never the only evidence for a DOC fact), `UNK` (not confirmed), `DECISION` (an operator decision of the root's `_decisions.csv` states it; see Decisions).
- Canonical forms: `[DOC <id>, <id>]`, `[CODE <id>: path#symbol]` (or `path#L10-L20`), `[DER <id>: how]`, `[COMMUNITY <id>]`, `[UNK]` or `[UNK: why]`, `[DECISION <decision id>]` or `[DECISION <decision id>: note]`. `_tools/kbfacts.py` parses them for every tool (grammar in its docstring); the kb-verify lint reports a DOC or COMMUNITY tag without an id. An internal root's or `kb/_self`'s fact may also cite an observed signal as `[LOG <log row id>]` (Logs); a public root never does.
- Numbers, dates, versions and table rows come from the source's own text or image, never from a fetch tool's summary of it: a summary can invent rows that the page does not have.
- `UNK` and `COMMUNITY` facts are leads to verify, not a basis to build on.
- A fact that rests on a run of our own (a probe, a measurement, a command we ran and watched) records one observation, not a rule:
  - tag it `DER` with the ids of the documented facts it rests on and say in the note what was run and read;
  - state in the fact the version of what ran (`Claude Code 2.1.285`, `dsc 3.3.0`, `git 2.47.1`) and the setup (OS, shell, headless or interactive, the date);
  - what the run did not cover (another mode, OS or version) is said in the fact or kept as an `UNK` fact, never folded into a general claim.

  The failure it answers: a job-object fact (`kb/public/python/stdlib-windows-portability.md`) first turned one headless probe into a claim about every session; it now names Claude Code 2.1.285, headless and interactive. The kb-verify lint warns on a `DER` Facts bullet (not a `SNIPPET:`) that says it rests on a run (`observed` or `measured` followed by `on`, `in`, `by`, `with`, `against`, `at`, `when`, `running` or `:`; `probed`; `the same probe against`, `a probe of`; `in the headless runs`, `in two runs`; not `in the long run` or `in a pipeline run`) and names no version (a dotted number such as `2.1.285` or `3.3`, `version N` or `vN`; a measurement such as `2.5 s` or `TLS 1.2` is no version). A live service with no version still warns: name the date and endpoint and judge the warning.

## CODE: what the implementation does

- Use `CODE` when the evidence is source code rather than documentation (a default read from a settings file, a limit in a validator, undocumented behaviour). It is implementation, not a promise: it can change in any release, and an answer built on it must say so. When the documentation states the same thing, the fact is `DOC`.
- A published contract is `DOC`, not `CODE`: a machine-readable schema or API definition (JSON Schema, Graph CSDL metadata, MCP `schema.ts`, OpenAPI/swagger, `.proto`, ECS or OTel metadata, a STIX bundle) is the promise itself. Build files and example configs next to it (`schemas.config.yaml`, `example_recognizers.yaml`) are `CODE`. `kbfacts.contract_source` draws this line for `lint.py --candidates`.
- The source row must be pinned: a repository file url at a release tag or commit (`raw.githubusercontent.com/<owner>/<repo>/<tag>/...`, `github.com/.../blob/<sha>/...`, `gitlab.com/.../-/raw/<tag>/...`, or the same `/-/raw/<commit>/` form on a self-managed GitLab host for a team's repositories) or a pinned artifact (`artifact_sha256`), never a branch. When upstream moves, add a new pinned row and set `superseded_by` (as for any replaced source).
- The note is a pointer into that file: `path#symbol` (a function, class, constant or key) or `path#L10-L20`. The lint rejects a CODE part without an id, without a pointer, or citing an unpinned source. It takes the first `path#symbol` of the note as the pointer and accepts text after it, so a fact from an ingested repository may name the relation it rests on there (`[CODE <id>: src/app.py#run, imported by src/cli.py]`); `kbingest.py drift` compares the same first pointer. A path whose first segment is a host name (`github.com/o/r/x#y`) or a pair of prose words (`and/or#x`) is no pointer.
- Borderline evidence: a release binary's own `--help` output is `DOC` (the published interface); a doc comment in source (rustdoc, docstrings) is `CODE`; that something is absent from a release archive is `DER`, with the derivation.
- In `kb/_self/` only, a CODE part may point into this repository without a source row: `[CODE _tools/kbfacts.py#pack]`. A test checks that the file and the symbol exist; `kb/_self/` never enters the pack.

## SNIPPET: a code example with evidence

- A code example is a bullet that starts `SNIPPET:`, directly above its fenced block: `- SNIPPET: <what it does>; context: <versions, prerequisites>; checked: no|syntax|run [DER <id>, <id>: parameters from the cmdlet page]`.
- The bullet carries an evidence tag other than `UNK`: a snippet nobody can back stays out. `checked:` says what was verified: `no`, `syntax` (parsed: the lint re-parses json, toml and python blocks), or `run` (executed in the stated context; say where in the note).
- Placeholders only, as in every example. The pack shows the bullet with `path:line` and its code block indented below it, counted in the budget; `rag.py show` prints the block too.
- A block without a `SNIPPET:` bullet is illustration only (Reference and Examples may keep them) and carries no evidence.
- A reader checking a snippet reads each parameter's reference page before dropping it: an article's own sources not showing a parameter does not mean it does not exist.

## Ids

- **Sources.** Add the source row before the fact. A new source's row is written with `python3 _tools/kbid.py add <URL> --title T --publisher P --licence L --reuse R [--version V] [--sha256 H] [--root NAME]`, never appended with a CSV writer or by hand: it takes the id, `S-` + 8 characters hashed from the url (so parallel writers converge; `kbid.py url <URL>` prints the id alone), sets `retrieved_utc` to today, leaves `used_in` and `superseded_by` empty, quotes the fields and prints the id to cite. Never invent an id or take "the next number". Legacy `S<number>` ids (`S100` ... `S2204`) stay valid and are never renumbered; reuse the existing id when the url already has a row. `check.py` rejects a hash id that does not match its url.
- **Replaced sources.** When a source is replaced (e.g. a pinned commit url whose upstream changed), add a new row (`kbid.py add`), set the old row's `superseded_by` to the new id, and re-point the citations of the facts you re-verified. Ids are never deleted or reused.
- **Answers.** New `_answers.md` entries are headed `## QK-<slug>. <question>` (`python3 _tools/kbid.py answer "<question>"`); an id never appears twice.
- Write the other CSVs (not `_sources.csv` rows: `kbid.py add`, above) with a real CSV writer (Python's `csv` module, `lineterminator="\n"`: its default ends rows with `\r\n`), one record per line: an unquoted comma breaks the row. The ledgers, the `_tools/` data and `kb/_self/` must stay `\n`-only (tested).

## Ledgers and retrieval data

- Failed lookups go in `_gaps.md`, disagreements in `_conflicts.md`. Each new entry ends with `(topic: <domain>/<slug>)` so `rag.py audit` links it to its article (`check.py` rejects a marker naming no topic).
- A later note on a `_gaps.md` entry is an indented bullet under it, starting with its word and date: `  - Resolved <date>: ...` (or `Superseded`) closes the entry, `  - Tried <date>: ...` (or `Partly resolved`) records what was tried and leaves it open; the query log's research queue reads these (`kb/_self/querylog.md`, The research queue).
- Retrieval data in `_tools/` (CSV writer, one row per line):
  - a topic about code with distinctive names (classes, API routes, libraries, scopes) gets `signals.csv` rows (`signal,topic`) for `topics-for`;
  - a product known by other names gets `aliases.csv` rows (`term,canonical`, term lowercase);
  - a real lookup that missed an article the kb has becomes a `lookup_eval.csv` row, id `python3 _tools/kbid.py eval "<question>"` (`EV-<slug>`). `python3 _tools/rag.py eval` must pass every question.
- After rewording or removing facts, `python3 _tools/doc2query.py stale` lists orphaned expansion keys (exit 1); `doc2query.py prune` removes their rows (regenerate only where real lookups miss; `kb/_self/doc2query.md`).
- Save structured data as a pinned artifact, with a row in `_artifacts.csv` and a digest.

## Licensing and privacy

- Each source's licence is recorded in `_sources.csv`: `licence` in words (the licence or terms, and where they are stated), `reuse` as one class. `check.py` rejects an empty `licence` and a `reuse` outside these (`kbcommon.REUSE`):
  - `copy`: an open licence allows a verbatim copy and redistribution with attribution (MIT, Apache-2.0, BSD, CC BY, CC BY-SA with its share-alike condition, CC0, GPL, public domain, US Government work, the EU reuse decision).
  - `quote`: no reuse licence (terms of use, all rights reserved, a no-licence repository, NC or ND licences, source-available licences such as BUSL-1.1): paraphrase, quotes of 25 words or fewer.
  - `paraphrase`: the terms forbid copying the text: paraphrase and cite ids only, no quotes. CIS Benchmark and ISO text.
  - `unknown`: the terms could not be read or determined; treated as `paraphrase`.
- A Microsoft Learn page is `copy` when its public mirror (the page's `github_feedback_content_git_url`) is live and licensed (CC BY 4.0, entra-docs MIT), and `quote` under the Learn terms when the mirror is private, gone or archived (an archived mirror's licence covers only the archived text) or its licence files conflict (`microsoft-graph-docs-contrib`). A MicrosoftDocs file pinned at a commit follows its repository's LICENSE.
- Facts are in our own words; quotes of 25 words or fewer. Verbatim copies only from `copy` sources, with attribution.
- **Snapshots.** A root keeps the normalized text of its live `copy` sources in `<root>/_snapshots/<id>.txt` (`python3 _tools/factdiff.py snapshot`; `factdiff.py detect` rewrites a changed one), so git diffs them. Each file's header is its attribution: source id, url, title, publisher, licence and the date taken, and the changes made (normalized to text). A snapshot stays under the licence its header names, not the repository's; share-alike text (CC BY-SA, GitLab `doc/`) stays share-alike. No snapshot for `quote`, `paraphrase` or `unknown` sources (their old text comes from upstream: the public docs repository at a commit, or a Wayback capture), for a pinned url (its text is the upstream file at the pin), for a JSON API answer, for a document over the `[snapshot]` size cap in `_tools/factdiff.toml`, or for a page that holds a private key header (a vendor's sample key, even the bare marker, would trip the secret scan). The directory's `README.md` says the same to readers; the lookup tools and the leak scan's placeholder rules skip it, while the secret scan covers it, with documented sample values in `_tools/tests_allowlist.txt` (vendor text, like pinned artifacts).
- Placeholders only in examples: hosts `PL-LT-00123` and `PL-SRV-0042`, domain `corp.example.com`, tenant `00000000-0000-0000-0000-000000000000`, user `jan.kowalski`. Never real hostnames, tenants, people or secrets in a `public` root, the tools or the docs. Organisation-specific knowledge belongs in an `internal` root (Roots, above).

## Decisions

Any root and `kb/_self/` may keep two CSV files; `kbcommon` names them, their columns and the `D` id prefix (`DECISIONS`, `DECISION_MAKERS`, `DECISION_COLS`, `MAKER_COLS`, `DECISION_ID`), and `check.py` checks them (the planted failures are the tests named `decisions_store`). Both are optional; a file that exists has exactly the header below.
- **`_decisions.csv`**, one row per decision, never deleted:
  - `id`: `D-<8 base32>` like a source id, unique in the file; `D` is a reserved root prefix (`kbcommon.RESERVED_PREFIXES`).
  - `text`: the decision. `by`: who made it, as the root stores a decision maker; `by_ref`: the id of a row of the root's own `decision-makers.csv`, else of the central register `kb/_self/decision-makers.csv`; a `by_ref` that resolves to neither is an error, and a `by` in a root that keeps no names needs its `by_ref`. Every decision names a maker but a `proposed` one and an `invalidated` one that was never active: a rejected proposal, which no one confirmed, has an empty `by` and `by_ref`, while a decision that was active and was invalidated later keeps the maker it had (`check.py` tells them apart by that, and the planted failures are the tests named `kbdecide_withdraw`).
  - `source`: where it was made; a source id in it must be one the root may cite. `date`: `YYYY-MM-DD`.
  - `context`: the things it is about, `;`-separated `kind:value` references, at least one: `item:<backlog id>`, `fact:<12-hex fact key>`, `source:<source id>`, `article:<domain>/<slug>`, `domain:<domain>`. In `kb/_self/` an article or a domain is written `<root>/<path>` (`article:public/auth/kerberos`). A source, article or domain must exist unless the decision is `invalidated`; an item or a fact that is gone is not an error here: `kbdecide.py sweep` invalidates a `proposed` or `active` decision when an `item:` is dropped (its file says so, or, when the file was deleted by sprint close or by `backlog.py drop` outside a sprint, its last version in git history is not done; done, or deleted as done, does not), a `source:` has a `superseded_by`, an `article:` or a `domain:` is gone, or `review_by` is before today, and writes the reference into `invalidated_reason` (`item:<id> dropped`), while a `fact:` whose key no longer exists is not invalidated: the sweep flags the decision with the likeliest current fact (`relink`) and changes no row, and `kbdecide.py relink ID --fact PATH:LINE` (open to agents) repoints the reference to the key of the fact at that line, refused when no fact starts there, and notes the old key in `links`. The planted failures are the tests named `decision_sweep` and `decision_sweep_relink`.
  - `status`: `proposed`, `active`, `invalidated` or `superseded`. `invalidated_reason` and `invalidated_date` are set exactly when the status is `invalidated`. `kbdecide.py invalidate` takes a `proposed` decision as well as an `active` one and is open to agents (the context sweep, and a proposal nobody should confirm); `confirm`, `record` (propose and confirm in one write; `backlog.py answer --record` uses it for an operator's gate answer), `supersede` and `restore` are the operator's (`--by operator`). `restore` returns an invalidated decision to `active` when a maker confirmed it and to `proposed` when none did, so a rejected proposal is never made active by a restore.
  - `supersedes`: `;`-separated ids of other decisions of the file; a `superseded` decision is named by another. `review_by`: empty or a date. `links`: free text.
- **`decision-makers.csv`**: `id` (a lowercase slug, unique), `role` (required), `name`, `source` (cited as any data file's source column is). `kb/_self/decision-makers.csv` is the central register. A root's storage policy for its makers is one reserved row, `id` `_policy` (no slug, so no maker has it) with the policy in `role` and `name` and `source` empty: `role-only`, `role-and-name` or `central-register`. A root with no policy row has none, and `kbdecide.py` refuses its first decision until the operator sets one (`kbdecide.py makers ROOT --policy P --by operator`; `kbroot.py` leaves it unset, so there is no default). `check.py` finds the policy value not one of the three, a second policy row, a name or a source on it, `role-and-name` in a root that is not internal, any policy row in `kb/_self/` (the central register holds roles only and has none), and under `central-register` a maker row of the root's own.
- **The `DECISION` tag.** A fact that rests on a decision cites it as `[DECISION <decision id>]` or `[DECISION <decision id>: note]`, the id being a decision's `D-<8 base32>` (`kbfacts.KINDS`; the part's `decision` holds the id and its `ids` stay empty, so no tool reads it as a source). `check.py` resolves each id, in a root's Markdown files and in the cells of its CSV data rows alike, to a row of its own root's `_decisions.csv`: an unknown id, a malformed one, a tag with no id and another root's id are errors (the planted failures are the tests named `decision_tag`). Files outside the roots (`kb/_self/`, `README.md`) may cite any root's or `kb/_self`'s decisions, and prose there that explains the tag writes its id as a placeholder that does not start `D-` (`<decision id>`). `kb_facts`'s `tags` and the query log's line tags accept the kind. Research never emits it: `ql_research.RESEARCH_TAGS` stays `DOC` and `COMMUNITY`, and a reply whose tag or text carries `DECISION` is rejected.
- **Lookups show decisions.** `pack` and `show` print a root's active and proposed decisions beside the facts they are tied to (a fact that cites the id, a `fact:`, `article:`, `domain:` or `source:` context that names what is printed) or whose text answers the question, labelled `decided` or `proposed (not confirmed)`; `--invalidated` (MCP `include_invalidated`) adds the invalidated ones as `invalidated because <reason>`, and a `superseded` one is never shown. An active decision that answers the question counts toward coverage `good`, a proposed or an invalidated one never; `audit` lists active decisions that share a context reference as possible contradictions and blocks nothing. The rules, with the budget and the match, are in `kb/_self/tools.md`, "Decisions beside the facts" [CODE _tools/kbfacts.py#decisions_for].
- **Names.** Only an internal root may hold a person's name (`kbcommon.maker_names_allowed`, which also asks the root's storage policy: `role-only` and `central-register` keep no names). `kb/_self/` is published, so it is not one: the central register holds roles only. In `kb/_self/` and in any root that is not internal the `name` of a maker is empty, and a decision's `by` is the role of the maker its `by_ref` names, so the files hold roles only.

## Logs

Any root and `kb/_self/` may keep one private CSV of observed signals, `_logs.csv`, optional like the decision files; `check.py` names it, its columns and the id form (`LOGS`, `LOG_COLS`, `LOG_ID`), and checks it (the planted failures are the tests named `log_row_contract`). A row is a derived aggregate about the project's own operation (a count, a median, a range over some days), never an event or a text: it names the runs of the query log's store it came from and the dates it covers.
- **Columns**, the exact header: `id` (`L-<8 base32>`, unique in the file; `L` is a reserved root prefix, which `check.py` refuses a root to take), `observation` (one short line with a number in it), `source_run_ids` (`;`-separated query-log run ids, `<yyyymmdd>T<hhmmss>Z-<8 hex>`, at least one, each once), `observed_from` and `observed_to` (`YYYY-MM-DD`, in order), `context` (the things it is about, as a decision's: `;`-separated `kind:value` references, at least one; an `article:` or `domain:` of a row that is not invalidated must exist), `status` (`proposed`, `active` or `invalidated`), `invalidated_reason` (set exactly when the status is `invalidated`) and `links` (free text).
- **No raw text.** The free-text cells (`observation`, `context`, `invalidated_reason`, `links`) are refused when they hold a line break, a JSON object, a timestamp with a time of day, a leak-scan hit (`kbcommon.leak_hits`) or more characters than `LOG_TEXT_MAX`, and an observation with no number is refused too: the shapes of a raw spool or ops event and of free text, not a proof that a row is an aggregate, which the operator confirms when a row becomes `active`.
- **The `LOG` tag.** A fact of an internal root or of `kb/_self` cites a row as `[LOG <log row id>]` (or after another tag: `[DOC <id>; LOG <log row id>]`). `check.py` resolves it as it resolves a `DECISION` tag, one resolver for both (`ledger_cite_error`): to a row of its own root's `_logs.csv`, in a Markdown file or a CSV data row; an unknown id, a malformed one, a tag with no id and another root's id are errors, and files outside the roots may cite any root's or `kb/_self`'s rows. A `LOG` tag in a file of a public root is an error whatever it names. `kbfacts` parses the kind but a `LOG` part is no evidence: a unit's `tags` leave it out, so it adds to no count and no verdict. The lookup tools print the active rows tied to a lookup's articles as observed signal beside the facts (`kb/_self/tools.md`, "Observed signals beside the facts"), never as coverage.
- **Recording and sweeping.** `python3 _tools/kblog.py` writes the file through the row store `kbdecide.py` keeps for the decisions (one store with a `Ledger` for each file, not a copy): `record` adds a `proposed` row (open to agents; the raw-text rules above are `check.py`'s, so a refused row leaves the file as it was), `propose --since DAY` adds the aggregates it derives from the query log's ops sidecar the same way, one row for each event and context with the runs and days of its rows, and a second run adds none (an aggregate in the file, in any status, is skipped), `confirm --by operator` makes it `active`, the operator's alone, and a row names no maker. A row stays `active` until its context is invalidated: `sweep` (open to agents) sets `invalidated` and the reason, naming each reference that broke (an `item:` dropped, a `source:` superseded, an `article:` or `domain:` gone, or a `fact:` that no fact has any more, which a decision's sweep only flags for `relink`, since a pointer to another fact would claim what was not observed) and notes the day in `links`, and the row stays in its file, as a decision's does. The id is `L-` and 8 base32 characters of the sha256 of the observation, context, runs and dates. The planted failures are the tests named `kblog_record_confirm`, `kblog_propose_from_ops`, `kblog_propose_converges` and `kblog_sweep_invalidates_with_context`.
- **Never public.** The public projection leaves every `_logs.csv` out at any depth, and `publish`, `check-public`, the push guard and the bridge refuse a history that holds one (`kb/_self/git.md`, "Public home"; the tests named `publish_omits_logs_csv`).
