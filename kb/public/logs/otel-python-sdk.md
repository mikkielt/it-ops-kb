# OpenTelemetry Python SDK: OTLP/HTTP export, observable gauges, Prometheus reader, spans and log events

## Summary
A Python process exports telemetry with the `opentelemetry-sdk` package and, for OTLP over HTTP, `opentelemetry-exporter-otlp-proto-http`, which sends protobuf bodies; a separate beta package sends OTLP JSON. The metric exporters read their endpoint, headers and timeout from the standard `OTEL_EXPORTER_OTLP_*` variables, with a per-signal variable taking the place of the generic one.
An observable gauge is a callback that the metric reader runs at each collection, which for `PeriodicExportingMetricReader` is once per interval and for the Prometheus reader once per scrape.
The Prometheus reader does not listen on a port itself: it registers with `prometheus_client`, whose `start_http_server` binds all interfaces unless an address is given. Spans take nanosecond start and end times and a parent through a context; a log record carries an `event_name` and attributes through `Logger.emit`.
The wire format and server side are in `logs/otel-collector-otlp-pipeline` and `claude/otel-monitoring`.

### OTLP/HTTP body format and Content-Type
- The proto exporter's default request headers are `Content-Type: application/x-protobuf` and `User-Agent: OTel-OTLP-Exporter-Python/<version>`. [CODE S-rto5it2w: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/__init__.py#_OTLP_HTTP_HEADERS]
- The proto metric exporter encodes an `ExportMetricsServiceRequest` and sends `SerializeToString()` bytes, so its body is binary protobuf. [CODE S-3ocg3rma: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/metric_exporter/__init__.py#OTLPMetricExporter._export_batch]
- The JSON exporter package sets `content-type: application/json` and a `User-Agent` of `OTel-OTLP-JSON-Exporter-Python/<version>` in its default headers. [CODE S-gn4cbgug: exporter/opentelemetry-exporter-otlp-json-http/src/opentelemetry/exporter/otlp/json/http/_internal.py#_resolve_headers]
- The OTLP specification requires a protobuf client request to carry `Content-Type: application/x-protobuf` and a JSON one `application/json`, and the server to answer with the content type it received. [DOC S-v2wnj4qk]
- Default headers are merged in order: the defaults (names lowercased), then the headers from the environment variable, then the `headers` argument (names lowercased), so a caller-supplied `content-type` replaces the default. [CODE S-4kd2fl7f: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/_common/__init__.py#_resolve_headers]

### Endpoint, headers and per-signal variables
- A per-signal endpoint variable (for metrics `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT`) is used as-is when set; otherwise `OTEL_EXPORTER_OTLP_ENDPOINT`, or `http://localhost:4318` when that is unset, has one trailing `/` removed and `/v1/metrics`, `/v1/traces` or `/v1/logs` appended. [CODE S-4kd2fl7f: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/_common/__init__.py#_resolve_endpoint]
- The `endpoint` constructor argument of the metric exporter wins over both variables and is the full URL including the signal path; its docstring says to set the generic variable for a base URL. [CODE S-3ocg3rma: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/metric_exporter/__init__.py#OTLPMetricExporter]
- Headers come from `OTEL_EXPORTER_OTLP_METRICS_HEADERS` when that is non-empty, else from `OTEL_EXPORTER_OTLP_HEADERS`; the two are not merged. The helpers take the variable name as an argument, and the trace and log exporters' own calls to them were not read. [CODE S-4kd2fl7f: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/_common/__init__.py#_resolve_headers; CODE S-3ocg3rma: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/metric_exporter/__init__.py#OTLPMetricExporter]
- A headers value is a comma-separated list of `name=value` pairs in the W3C baggage header form: optional spaces around the name and value, the value percent-encoded, names and values percent-decoded and stripped, names lowercased, and any `=` after the first part of the value. The exporter parses it with `liberal=True`, which also accepts a value holding a literal space; a pair that matches neither form is skipped with a warning, and semicolon metadata is not supported. [CODE S-6avl2ftj: opentelemetry-api/src/opentelemetry/util/re.py#parse_env_headers]
- The value characters the pattern allows leave out the space (strict form only), the double quote, comma, semicolon and backslash, so a value holding a comma or semicolon has to be percent-encoded. [CODE S-6avl2ftj: opentelemetry-api/src/opentelemetry/util/re.py#_VALUE_FORMAT]
- The timeout is read from `OTEL_EXPORTER_OTLP_METRICS_TIMEOUT`, else `OTEL_EXPORTER_OTLP_TIMEOUT`, else 10, parsed as a float and used as seconds; an invalid value logs a warning and falls back to 10. [CODE S-4kd2fl7f: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/_common/__init__.py#_resolve_timeout]
- The specification gives the exporter timeout (default 10 s, `OTEL_EXPORTER_OTLP_TIMEOUT` and its per-signal forms) the type Timeout, an integer number of milliseconds with `12000` meaning 12 seconds, while the code above reads the same variable as seconds, so `10000` there would mean 10000 seconds; the code decides what a Python process does (`_conflicts.md`, this topic). [DOC S-rcmsm2rb, S-56w77twg vs CODE S-4kd2fl7f, unresolved]
- Compression is read from the per-signal `..._COMPRESSION` variable, else `OTEL_EXPORTER_OTLP_COMPRESSION`, else `none`; the values are `none`, `gzip` and `deflate`, an unsupported one logs a warning and means `none`, and a compressed request carries a `Content-Encoding` header. [CODE S-4kd2fl7f: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/_common/__init__.py#_resolve_compression; CODE S-mi6kw3ft: exporter/opentelemetry-exporter-otlp-common/src/opentelemetry/exporter/otlp/common/http.py#_OTLPHTTPClient.__init__]
- Server certificate, client key and client certificate follow the same rule (the argument, then the per-signal variable, then the generic one; without any, the `requests` default of verifying the server). [CODE S-4kd2fl7f: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/_common/__init__.py#_build_transport]
- The exporter classes read no protocol variable. The SDK's environment-based configuration (`OTEL_METRICS_EXPORTER=otlp` and the like) reads `OTEL_EXPORTER_OTLP_<SIGNAL>_PROTOCOL`, else `OTEL_EXPORTER_OTLP_PROTOCOL`: with none set `otlp` means the gRPC exporter, `grpc` means gRPC, `http/protobuf` means the proto HTTP exporter, and any other value, `http/json` included, raises `RuntimeError` ("Unsupported OTLP protocol"). [CODE S-xzukzvfm: opentelemetry-sdk/src/opentelemetry/sdk/_configuration/__init__.py#_EXPORTER_BY_OTLP_PROTOCOL; CODE S-4kd2fl7f: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/_common/__init__.py#_resolve_endpoint; CODE S-3ocg3rma: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/metric_exporter/__init__.py#OTLPMetricExporter]

### Retries and partial success
- For a partial success the OTLP/HTTP server answers `HTTP 200 OK` with the usual `Export<signal>ServiceResponse` and a `partial_success` field holding the number rejected (`rejected_spans`, `rejected_data_points` or `rejected_log_records`) and, as a SHOULD, an English `error_message`; a server may also set `error_message` with a rejected count of 0 as a warning. [DOC S-v2wnj4qk]
- A client must not retry a response whose `partial_success` is populated. [DOC S-v2wnj4qk]
- A client should retry only `429 Too Many Requests`, `502`, `503` and `504`; every other `4xx` or `5xx` code must not be retried, and `400 Bad Request` (undecodable or invalid data) is explicitly final. [DOC S-v2wnj4qk]
- On `429` or `503` the server may send `Retry-After` (seconds or an HTTP date), which the client should honour, else it should back off exponentially; a failed connection is retried with exponential backoff and random jitter. [DOC S-v2wnj4qk]
- The Python client treats any status from 200 to below 400 as success without reading the response body, so a `partial_success` is neither parsed nor logged. [CODE S-mi6kw3ft: exporter/opentelemetry-exporter-otlp-common/src/opentelemetry/exporter/otlp/common/http.py#_OTLPHTTPClient.export]
- The Python client retries the same four codes, up to 6 attempts, with a backoff of 2 to the power of the attempt number seconds times a random factor from 0.8 to 1.2; it uses `Retry-After` (seconds or HTTP date) when present, retries a connection error once at once, and gives up when the next wait would pass the export timeout or on shutdown. [CODE S-mi6kw3ft: exporter/opentelemetry-exporter-otlp-common/src/opentelemetry/exporter/otlp/common/http.py#_RETRYABLE_STATUS_CODES]
- The metric exporter refuses to send a request over its `max_request_size` (default 64 MiB, measured before compression) and counts it as a failed export; `max_export_batch_size` splits a batch by data points. [CODE S-3ocg3rma: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/metric_exporter/__init__.py#OTLPMetricExporter]

### Observable gauges and the periodic reader
- `Meter.create_observable_gauge(name, callbacks=None, unit="", description="")` takes callbacks that return an iterable of `Observation`, or a generator that yields such iterables. [CODE S-5chmnjba: opentelemetry-api/src/opentelemetry/metrics/_internal/__init__.py#Meter.create_observable_gauge]
- `Observation(value, attributes=None, context=None)` holds one value and its attributes; an asynchronous callback returns or yields these. [CODE S-lsg4pugj: opentelemetry-api/src/opentelemetry/metrics/_internal/observation.py#Observation]
- A generator callback is advanced to its first `yield` when the instrument is created; each collection sends the `CallbackOptions` into it, and after it ends it returns nothing. [CODE S-yt3dat5p: opentelemetry-sdk/src/opentelemetry/sdk/metrics/_internal/instrument.py#_Asynchronous.__init__]
- For each callback result the SDK stamps the observation with `time_ns()` at that moment, drops a non-finite value with a warning, and logs an exception raised by a callback ("Callback failed for instrument") without raising it. [CODE S-yt3dat5p: opentelemetry-sdk/src/opentelemetry/sdk/metrics/_internal/instrument.py#_Asynchronous.callback]
- A collection runs every registered asynchronous instrument's callbacks in turn under the reader's collection call, with `CallbackOptions` carrying a timeout once less than 10 s remain, and raises `MetricsTimeoutError` if the deadline passes while a callback runs. [CODE S-xemeq5o7: opentelemetry-sdk/src/opentelemetry/sdk/metrics/_internal/measurement_consumer.py#collect]
- `PeriodicExportingMetricReader` takes `export_interval_millis` (default from `OTEL_METRIC_EXPORT_INTERVAL`, else 60000) and `export_timeout_millis` (from `OTEL_METRIC_EXPORT_TIMEOUT`, else 30000); an interval of `math.inf` disables the periodic collection and an interval of 0 or less raises `ValueError`. [CODE S-d46zfljm: opentelemetry-sdk/src/opentelemetry/sdk/metrics/_internal/export/__init__.py#PeriodicExportingMetricReader]
- The reader starts a daemon thread that waits one interval before its first `collect`, so the first run of a gauge callback is one interval after the reader is created, and then repeats; `force_flush` and `shutdown` also collect, and the exporter's `export` is never called concurrently. [CODE S-d46zfljm: opentelemetry-sdk/src/opentelemetry/sdk/metrics/_internal/export/__init__.py#PeriodicExportingMetricReader._ticker]
- Each reader collects on its own, so a callback runs once per periodic interval and once per Prometheus scrape when both readers share one meter provider; a callback has to be cheap and safe to call at any time. [DER S-xemeq5o7, S-d46zfljm, S-qpknqjro: the consumer loops over the async instruments on every reader's collect]

### The Prometheus reader and /metrics
- `PrometheusMetricReader(disable_target_info=False, prefix="", scope_info_enabled=True, *, resource_attribute_filter=None, registry=REGISTRY)` prefers cumulative temporality and registers a collector with a `prometheus_client` registry (the global one by default); it opens no socket. [CODE S-qpknqjro: exporter/opentelemetry-exporter-prometheus/src/opentelemetry/exporter/prometheus/__init__.py#PrometheusMetricReader]
- The module's usage example starts the HTTP side itself with `prometheus_client.start_http_server(port=8000, addr="localhost")` before creating the reader. [CODE S-qpknqjro: exporter/opentelemetry-exporter-prometheus/src/opentelemetry/exporter/prometheus/__init__.py#module-docstring]
- The collector calls the reader's `collect` each time the registry is gathered, for example when Prometheus fetches the endpoint, so observable gauge callbacks run at every scrape and `target_info` is added unless disabled. [CODE S-qpknqjro: exporter/opentelemetry-exporter-prometheus/src/opentelemetry/exporter/prometheus/__init__.py#_CustomCollector.collect]
- `start_http_server` is an alias of `start_wsgi_server`, whose `addr` defaults to `0.0.0.0`; for a loopback-only `/metrics` the address is passed explicitly. [CODE S-3ylk7y4h: prometheus_client/exposition.py#start_wsgi_server; see logs/prometheus-retention-exposition]
- Only the auto-instrumentation class `_AutoPrometheusMetricReader` reads `OTEL_EXPORTER_PROMETHEUS_HOST` (default `localhost`) and `OTEL_EXPORTER_PROMETHEUS_PORT` (default `9464`) and starts the server; a directly built `PrometheusMetricReader` ignores both variables. [CODE S-qpknqjro: exporter/opentelemetry-exporter-prometheus/src/opentelemetry/exporter/prometheus/__init__.py#_AutoPrometheusMetricReader.__init__]
- `shutdown` of the reader unregisters its collector from the registry. [CODE S-qpknqjro: exporter/opentelemetry-exporter-prometheus/src/opentelemetry/exporter/prometheus/__init__.py#PrometheusMetricReader.shutdown]

### Spans with explicit times and a parent
- `Tracer.start_span(name, context=None, kind=INTERNAL, attributes=None, links=None, start_time=None, record_exception=True, set_status_on_exception=True)` creates a span without making it current; the parent is the current span of `context`, by default the global context, and with none the span is a root. [CODE S-kzsjk7w6: opentelemetry-api/src/opentelemetry/trace/__init__.py#Tracer.start_span]
- `start_time` and `end_time` are integers set straight into the span, and the SDK uses `time_ns()` (nanoseconds since the epoch) when they are `None`; `Span.end(end_time=None)` raises `RuntimeError` on a span that was never started, ignores a second call with a warning, and makes the attributes immutable. [CODE S-ai2idcjy: opentelemetry-sdk/src/opentelemetry/sdk/trace/__init__.py#_Span.end]
- An explicit parent is passed as a context: `opentelemetry.trace.set_span_in_context(parent_span)` returns it and `tracer.start_span(name, context=ctx)` reads `get_current_span(context).get_span_context()`; the child takes the parent's trace id and a new span id, and a parent whose span context is not valid starts a new trace. [CODE S-adxo34qo: opentelemetry-api/src/opentelemetry/trace/propagation/__init__.py#set_span_in_context; CODE S-ai2idcjy: opentelemetry-sdk/src/opentelemetry/sdk/trace/__init__.py#Tracer.start_span]
- A span that already finished elsewhere is therefore recorded by `start_span(..., context=ctx, start_time=start_ns)` followed by `end(end_time=end_ns)`; and when only the parent's ids are known, a `NonRecordingSpan` built from a `SpanContext(trace_id, span_id, is_remote, trace_flags)` placed in a context serves as the parent. [DER S-ai2idcjy, S-kzsjk7w6, S-adxo34qo: the SDK reads only the span context of the context's current span; this was not run]

### Log records with an event name and attributes
- `Logger.emit(record=None, *, timestamp, observed_timestamp, context, severity_number, severity_text, body, attributes, event_name, exception)` accepts the fields directly or a `LogRecord`; `event_name` is an optional string, `observed_timestamp` defaults to `time_ns()`, and the trace and span ids come from the current span of the context. [CODE S-x74lzie5: opentelemetry-api/src/opentelemetry/_logs/_internal/__init__.py#Logger.emit]
- The SDK side is `opentelemetry.sdk._logs.LoggerProvider(resource=...)` with `add_log_record_processor(...)`, `get_logger(name, version, ...)`, and `BatchLogRecordProcessor` or `SimpleLogRecordProcessor` from `opentelemetry.sdk._logs.export`; the OTLP/HTTP exporter is `OTLPLogExporter` in `opentelemetry.exporter.otlp.proto.http._log_exporter`. [CODE S-tx2jwcse: opentelemetry-sdk/src/opentelemetry/sdk/_logs/_internal/__init__.py#LoggerProvider; CODE S-qtwfnvws: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/_log_exporter/__init__.py#OTLPLogExporter]
- The proto log encoder copies `event_name`, the encoded `attributes` and the severity number into the OTLP log record, so a protobuf receiver reads it from the record's `event_name` field (the JSON encoding's name for it is `eventName`, as in `claude/otel-monitoring`). [CODE S-ybidjd44: exporter/opentelemetry-exporter-otlp-proto-common/src/opentelemetry/exporter/otlp/proto/common/_internal/_log_encoder/__init__.py#_encode_log]
- The logs API and SDK modules are imported through underscore-prefixed paths (`_logs`); the Python documentation's stability statement for the logs signal was not read. [UNK]

### How it fits
- A tool that is otherwise standard-library only can keep the OpenTelemetry packages optional by importing them after the endpoint is set and by pinning the set above in its own lock file; the protobuf exporter brings `requests` and `opentelemetry-proto` with it, and the JSON exporter is beta. [DER S-omxbv3ul, S-ozi35eb7: dependency lists and the beta classifier]
- A local metrics endpoint on loopback needs `start_http_server(port, addr="127.0.0.1")` or `"localhost"` before the reader is created; relying on the reader alone opens no port and the library default would listen on all interfaces. [DER S-qpknqjro, S-3ylk7y4h: the reader registers only a collector; `start_wsgi_server` defaults to `0.0.0.0`]
- An exporter that must not block the caller sends from the reader's or the batch processor's thread, and a collector that answers `429`, `502`, `503` or `504` costs up to 6 attempts inside the export timeout; any other error code drops the batch with a logged error. [DER S-mi6kw3ft, S-d46zfljm: the retry loop and the periodic reader's thread]

## Examples
- SNIPPET: the pieces of a metrics export with an observable gauge, an OTLP/HTTP exporter and a loopback `/metrics`; context: package versions above, host and port are placeholders; checked: no [CODE S-5chmnjba: opentelemetry-api/src/opentelemetry/metrics/_internal/__init__.py#Meter.create_observable_gauge; CODE S-d46zfljm: opentelemetry-sdk/src/opentelemetry/sdk/metrics/_internal/export/__init__.py#PeriodicExportingMetricReader; CODE S-qpknqjro: exporter/opentelemetry-exporter-prometheus/src/opentelemetry/exporter/prometheus/__init__.py#PrometheusMetricReader; CODE S-4kd2fl7f: exporter/opentelemetry-exporter-otlp-proto-http/src/opentelemetry/exporter/otlp/proto/http/_common/__init__.py#_resolve_headers]
```python

from opentelemetry.exporter.otlp.proto.http.metric_exporter import OTLPMetricExporter
from opentelemetry.exporter.prometheus import PrometheusMetricReader
from opentelemetry.metrics import Observation
from opentelemetry.sdk.metrics import MeterProvider
from opentelemetry.sdk.metrics.export import PeriodicExportingMetricReader

# OTEL_EXPORTER_OTLP_ENDPOINT=http://collector.corp.example.com:4318
# OTEL_EXPORTER_OTLP_HEADERS=x-example=value%20one,x-other=two
start_http_server(port=9464, addr="127.0.0.1")
readers = [PrometheusMetricReader(), PeriodicExportingMetricReader(OTLPMetricExporter())]
provider = MeterProvider(metric_readers=readers)

def load_callback(options):
    yield Observation(0.5, {"host": "PL-LT-00123"})

provider.get_meter("example").create_observable_gauge("example.load", [load_callback])
```
