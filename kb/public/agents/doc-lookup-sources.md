# Documentation lookup sources for agents: stable MCP servers and APIs

## Summary
Three no-auth remote MCP servers cover most of this kb and are configured for every user in `.mcp.json`:
Microsoft Learn (GA, about 15 domains), Claude Code Docs and the MCP docs site. GitHub's remote MCP server
(GA, needs a token) reaches the source repositories behind many pinned artifacts and is optional. Plain APIs
(GitHub REST, Graph `$metadata`, PyPI JSON, `llms.txt`) cover scripted checks. The Microsoft MCP Server for
Enterprise (preview) is excluded, and GitLab's MCP server (GA since GitLab 19.5, needs a token) is not in the
table. Full table: `doc-lookup-sources.csv`.
Refreshing an existing fact still goes through `_tools/fetch.py --diff`; these servers are for finding and
reading the current page.

### Live search tools a routed lookup can call (checked 2026-09-29)
- Mintlify's generated MCP server has three tools: search (snippets with titles and links), query-docs-filesystem (shell-style reads of the site's virtual filesystem, including reads of several pages in one call) and submit-feedback; search takes optional `version` and `language` filters, and the skill.md files are exposed as MCP resources. [DOC S2182]
- Microsoft Learn's `microsoft_docs_search` returns up to 10 chunks of at most 500 tokens each with title, url and excerpt, `microsoft_code_sample_search` up to 20 samples (optional `language` filter), and `microsoft_docs_fetch` a whole page as Markdown, so a search adds at most about 5,000 tokens of tool result. [DOC S2177] [DER S2177: 10 x 500 tokens]
- Claude Code's `WebSearch` tool runs a query on Anthropic's web search backend and returns titles and urls only; it does not fetch the pages, so reading one takes a `WebFetch` call. One call may issue up to eight backend searches. [DOC S-3yod3u7q]
- An interactive terminal session has a limit of 200 `WebSearch` calls, counted across the main conversation and its subagents (v2.1.212 or later); at the limit a search does nothing and Claude is told to continue with what it has gathered or ask for more. `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` raises the cap (a positive whole number; the cap cannot be turned off), and from v2.1.290 that session's limit refills at about 100 calls per hour, which `CLAUDE_CODE_WEB_SEARCH_REFILLS_PER_HOUR` changes. [DOC S-3yod3u7q]
- The environment-variables page gives the refill default as 100 in an interactive terminal session and 0, which turns refill off, in a non-interactive session (v2.1.290 or later); the tools reference states the 200-call limit only for an interactive terminal session. [DOC S745] [UNK: whether a `claude -p` or Agent SDK run is subject to the 200-call cap]
- Permission rules for `WebSearch` take no specifier; the tool is available on the Claude API, Claude Platform on AWS and Microsoft Foundry, works on Google Cloud's Agent Platform with Opus 4, Sonnet 4, Haiku 4.5 and later models, and is not exposed by Amazon Bedrock. [DOC S-3yod3u7q]
- `WebFetch` asks for a url and a prompt, converts the page to Markdown and, for most fetches, runs the prompt over it in a separate model call, so Claude receives that call's result and the tool is lossy by design; it reads at most 100,000 characters of a page per call (from v2.1.290 the result says how much went unread), caches a response 15 minutes, fails a page not downloaded within five minutes (v2.1.268 adds `CLAUDE_CODE_WEBFETCH_DEADLINE_MS`), refuses hostnames without a dot, and for a redirect to a different host returns the original and target urls instead of following it. [DOC S-3yod3u7q]
- In Manual and `acceptEdits` permission modes `WebFetch` prompts before a fetch except for a built-in set of preapproved documentation domains and domains a rule allows; the page does not list that set, and an explicit `WebFetch(domain:...)` rule overrides it. [DOC S-3yod3u7q] [UNK: whether Microsoft Learn or the Claude and MCP docs hosts are in the preapproved set]
- `WebSearch` and `WebFetch` both need approval in a permission-prompting mode, and `-p` has no terminal to answer, so a headless researcher lists them in `--allowedTools` (which allows them without prompting and does not restrict which tools exist) or runs under a mode that skips the prompt. [DER S-3yod3u7q, S742, S1824: the prompt table and the `-p` no-TTY rule]

### What the three docs endpoints answer over plain HTTP (unauthenticated probe, 2026-09-29)
- A POST of `initialize` (protocol version `2025-11-25`, `Accept: application/json, text/event-stream`) to `https://learn.microsoft.com/api/mcp` was answered with protocol version `2025-06-18`, as `Content-Type: text/event-stream` holding one `event: message` block, and with an `mcp-session-id` header. A `tools/list` POST sent without that header was also answered `200`, so the server did not require the session id. [DER S2177: the request and the response headers seen; the version answer follows the negotiation rule in mcp/transports-streamable-http.md]
- The same probe against `https://code.claude.com/docs/mcp` and `https://modelcontextprotocol.io/mcp` was answered with protocol version `2025-11-25`, as `text/event-stream` with one `event: message` block, and with no session-id header; `tools/list` to the Claude Code endpoint answered `200` without a prior `initialize`. `curl` with its default user agent was accepted by both. Re-run on 2026-10-02 with `curl` 8.7.1 on macOS, the `initialize` response of both endpoints again carried protocol version `2025-11-25` and a `serverInfo` of name `Claude Code Docs` or `Model Context Protocol` with version `1.0.0`; the date of the run is what dates a live endpoint's answer. [DER S2180, S2181: the request and the response seen]
- All three responses carry `Cache-Control` values that forbid storing them (`no-cache, no-store` for Learn; `no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0` for the Claude Code endpoint; `no-cache, no-transform` for the MCP endpoint), so the responses give a client no lifetime to reuse for a search POST: a local cache keys on the server and the request body and picks its own lifetime. [DER S2177, S2180, S2181: the header values seen]

### Where a source states its licence, and a provider's own search API (read 2026-10-12)
- arXiv's licence page says the submitter chooses the licence and lists CC BY 4.0, CC BY-SA 4.0, CC BY-NC-SA 4.0, CC BY-NC-ND 4.0, the arXiv.org perpetual, non-exclusive license 1.0 and CC Zero; it adds that "different versions of the work can have different licenses" and that the licence chosen for a version is irrevocable. [DOC S-soqo5xvt]
- arXiv's API terms say "The vast majority of e-prints are submitted under the arXiv.org non-exclusive right to distribute", and that descriptive metadata about e-prints may be used under CC0 1.0; the e-prints themselves stay under their copyright. [DOC S-7ppiqh3x]
- The abstract page of an arXiv paper carries its licence as a link in a `div` of class `abs-license`: read with `curl` 8.7.1 on 2026-10-12, the page of 2503.18813 linked `http://creativecommons.org/licenses/by/4.0/` and the page of 1706.03762 linked `http://arxiv.org/licenses/nonexclusive-distrib/1.0/`. Two papers were read, both at the unversioned address, which shows the latest version; whether a versioned address shows that version's own licence link was not read. [DER S2006, S-u5diy2cr, S-soqo5xvt: the markup of two pages, with the per-version rule of the licence page]
- The arXiv API has a rate limit: its terms of use tell clients of the legacy APIs, the arXiv API among them, to "make no more than one request every three seconds, and limit requests to a single connection at a time"; the rate limit covers all machines under the caller's control. [DOC S-7ppiqh3x]
- The arXiv API's `search_query` takes field-prefixed terms, for example `ti` (title), `au` (author), `abs` (abstract) and `all`, joined with `AND`; `start` and `max_results` page the result, which is an Atom feed, with at most 30000 results per call in slices of at most 2000; the manual asks clients to "incorporate a 3 second delay" between calls. [DOC S-cig7twfc]
- GitHub's licence API uses Licensee to match a repository's `LICENSE` file against a short list of known licences, and "the API does not take into account the licenses of project dependencies or other means of documenting a project's license"; a matched licence's key and name follow SPDX. [DOC S-ezhoiiyb]
- So an `spdx_id` of `NOASSERTION` means the match against that list failed, not that the repository states no licence: the Vault repository holds BUSL-1.1 text and the API reported it as `NOASSERTION` (`prior-art/secret-vault-encryption.md`), so a tool that takes the API's value must send `NOASSERTION` and a missing `license` to a read of the `LICENSE` file. [DER S-ezhoiiyb, S1002: the documented match rule with the recorded mismatch]
- Observed unauthenticated with `curl` 8.7.1 on 2026-10-12: `GET /repos/microsoft/presidio/license` answered `301` to an id-based url (the repository was renamed, as above), and with redirects followed `200` with a `license` object holding `key` (`mit`), `name`, `spdx_id` (`MIT`) and `url`; each item of a `GET /search/repositories` result carried the same object, so one repository search both finds a project and reads its licence. [DER S-jkl2kuth, S-5uo7eb2c: one repository, one run]
- GitHub's search endpoints: "For unauthenticated requests, the rate limit allows you to make up to 10 requests per minute"; authenticated requests get 30 a minute, and code search "requires you to authenticate and limits you to 10 requests per minute"; one search returns at most 1,000 results, and a query over 256 characters (operators and qualifiers not counted) or with more than five `AND`, `OR` or `NOT` fails validation. [DOC S-t36jnjsm]
- GitHub code search needs authentication: an unauthenticated `GET /search/code` (the GitHub REST search API) answered `401` with the message "Requires authentication" on 2026-10-12, a request without a token. [DER S-mz6tic2a: one request]
- An unauthenticated `GET /rate_limit` lists a `code_search` bucket (`agents/doc-change-detection.md:97`), so a bucket's presence is no access: a tool with no token has repository search at 10 requests a minute and no code search. [DER S-mz6tic2a, S-5lkuonr6: one request each, one IP address]
- GitLab's `GET /projects/:id` "can be accessed without authentication if the project is publicly accessible"; its boolean `license` attribute includes the project's licence data, and the response then holds `license_url` and a `license` object with `key`, `name`, `nickname`, `html_url` and `source_url`. [DOC S-4yvdwu5c]
- The GitLab page's example gives the `license.key` as `lgpl-3.0`, a lowercase key and not an SPDX id (`LGPL-3.0-only`), and the page names no key vocabulary, so a tool maps the key to an SPDX id or compares it case-folded. [DER S-4yvdwu5c: the example response at the pinned commit]
- The PyPI API page lists the APIs it covers (Index, JSON, Upload, Integrity, Stats, BigQuery datasets, RSS feeds, secret reporting), none a search, and says "No new integrations should use the XML-RPC APIs as they are planned for deprecation". [DOC S-y6wauqrp]
- A project on PyPI is therefore found by its exact name through the JSON API (`pypi.org/pypi/<name>/json`) or by a general web search, not by keywords through a PyPI API. [DER S-y6wauqrp, S2192: the listed APIs and the JSON API's by-name route; a documented absence]
- Requested on 2026-10-12 with `curl` 8.7.1, `https://code.claude.com/docs/en/overview.md` and `https://modelcontextprotocol.io/specification/2025-06-18/basic/transports.md` both answered `200` with `content-type: text/markdown` and a `link` header naming the site's `llms.txt`; both are Mintlify-hosted, which generates a Markdown version of each page. [DER S-yftp4qw3, S-ywdbre2n, S1811: two pages, one run]
- Each source family of a new source row therefore has a licence record a tool can read: an arXiv abstract page's licence link, a GitHub repository's `license` object (`NOASSERTION` and a missing one need the `LICENSE` file), a GitLab project's `license` object, a Learn page's public mirror, and for Anthropic's docs the terms page; any other host has none and needs the researcher to read its terms. [DER S-u5diy2cr, S-ezhoiiyb, S-4yvdwu5c, S2195, S-fvspfpxd: the records read above and the Learn and Anthropic rules recorded earlier in this article]

## Examples
- SNIPPET: check the shared servers connect, then add a personal read-only GitHub toolset and search Learn
  without MCP; context: Claude Code 2026-09, `.mcp.json` at repo root, `GITHUB_PAT` a personal access token
  in the caller's own environment; checked: no [DOC S2179, S2187, S-el34o4bb: `claude mcp add`
  scope/transport/header syntax, the toolset URL, and the `npx @microsoft/learn-cli search` command]
```bash
# Shared servers are in .mcp.json; check they connect
claude mcp list

# Optional, per user: GitHub read-only repository tools (token from your own environment)
claude mcp add --scope user --transport http github-repos-ro \
  https://api.githubcopilot.com/mcp/x/repos/readonly \
  --header "Authorization: Bearer $GITHUB_PAT"

# Scripted, no MCP: Learn from the command line
npx @microsoft/learn-cli search "DSC v3 resource manifest"
```
