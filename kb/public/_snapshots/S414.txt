Feature Request: Group Managed Service Account Support
## Status update (2023-04-20)
This feature is available as of 15.5 with the [community contribution](https://gitlab.com/gitlab-org/gitlab-runner/-/merge_requests/2913) from @Jamesits. We need to revise the runner docs so its a bit more clear how to use this feature with Microsoft Group Managed Service Accounts (gMSA).
To use this feature with the Docker executor:
1. Users need to [prepare](https://learn.microsoft.com/en-us/virtualization/windowscontainers/manage-containers/manage-serviceaccounts) the container host.
1. Provide `security-opt` which is a `gitlab-runner` [configuration option](https://gitlab.com/gitlab-org/gitlab-runner/blob/467d1707c5439318b62c4e93d9d7ce12567613f1/common/config.go#L193-193). [Microsoft - Run a container with a gMSA](https://learn.microsoft.com/en-us/virtualization/windowscontainers/manage-containers/gmsa-run-container).
## Overview
I'd like to request Group Managed Service Account (gMSA for short) support for both the GitLab runner itself (as a service) and `docker-windows` executor. This would:
- allow a bunch of `docker-windows` build machines, all Active Directory joined, to have the same user identity for every GitLab runner, so that it is much easier to manage file permissions on network shared storage (SMB, etc.)
- allow GitLab runner and the build script to have different permissions, thus better enforcing ACLs
- allow programs running inside the container to authenticate to Active Directory with a domain user identity, so NT ACL and RBAC rules can be easily enforced on the build scripts
## Proposal
### ✅GitLab Runner Service Support
(Already supported; doc needs to be updated to remove the "required" description on the "password" argument as it is not required actually.)
This require the `gitlab-runner install` command to accept a gMSA account as username and NO (or empty) password. [[1]](https://www.advancedinstaller.com/install-service-under-managed-service-account.html) e.g.:
```powershell
. .\gitlab-runner-windows-amd64.exe install --user "CORP\Test-gMSA$"
```
### ✅gMSA Credential Spec Injection Support for `docker-windows` Executor
Docker for Windows already supports gMSA credential. The command line looks like:
```cmd
docker run --security-opt "credentialspec=file://contoso_webapp01.json" --user "NT AUTHORITY\NETWORK SERVICE" -it mcr.microsoft.com/windows/servercore:ltsc2019 powershell
```
We only need a way to configure GitLab runner's Docker interface to set up the required arguments. Thus, I propose the following changes:
#### ✅A smaller one so we can get the basic things running fast
- Support settings a user in gitlab-runner [docker advanced config](https://docs.gitlab.com/runner/configuration/advanced-configuration.html#the-runnersdocker-section) (I've implemented: https://gitlab.com/gitlab-org/gitlab-runner/-/merge_requests/2913 )
One'll have to register at least one runner per gMSA context, but it would just work fine.
Instructions on how to use this feature: https://gitlab.com/gitlab-org/gitlab-runner/-/issues/30945#note_1357888774
#### A bigger, full featured changeset (requires more discussion)
- GitLab Runner `config.toml`
- Add a string array typed property `runners[].docker.credential_specs[]` to match which credential spec files are available to the jobs
- Add a string typed property `runners[].docker.user` for setting the default user
- Allow setting path configs (e.g. `builds_dir`) with environment variables (e.g. `%TEMP%`)
- CI config `.gitlab-ci.yml`
- Add a string typed property `job_name.image.credential_spec` so a job can specify which credential spec file it want to load
- Support populating `security-opt` command line argument automatically from the `credential_spec` field
- Add a string typed property `user` to specify which user inside the container the job should start from
- GitLab GUI
- Perferably, add a config item in project settings to enforce the credential spec file name on a project level
BTW, there are already some discussion about setting an user in the CI config: https://gitlab.com/gitlab-org/gitlab-runner/-/merge_requests/3241#note_984772396
