# Tools

Every tool is stdlib-only Python in `_tools/`, run as `python3 _tools/<tool>`. Each tool's docstring (`--help`) is its full reference; this file is the one table of what exists and how the lookup tools decide. Lookup rules for agents are in `AGENTS.md`.

After changing the dev group: `uv lock`.

## How the lookup tools decide

- **One parser.** `pack`, `facts`, `audit` and `src --cited` read the kb through `_tools/kbfacts.py`, which parses fact units (bullets, table rows, data rows), tags (grammar in its docstring) and ledger entries one way for every tool.
- **The verdict.** `pack` ranks fact lines (BM25 with light stemming) and prints `coverage: none` when the question's named terms are not in the kb or most key words are missing, `weak` when the best article matches under 60% of the key words, else `good`. A word counts as a key word only when under a fifth of the kb's lines hold it. Untagged lines (printed `(no tag)`) can lift `none` to `weak`, never to `good`. `rag.py eval` checks this against `_tools/lookup_eval.csv`; `tests.py` runs it.
- **The `check:` line (a possible false `good`).** The verdict counts words, not meaning. Under a `good` verdict the pack prints `check:` when a name the question uses (a product, an id) appears nowhere in the lead article, or when no single fact holds half of 4+ key words. The `kb:` hook then passes the pack to the model instead of answering alone.
- **The index.** `pack`, `search`, the `kb:` hook and the MCP server read one persisted index: postings lists in a stdlib `sqlite3` file named after a fingerprint of the kb files. It lives in `_cache/` in a clone (`${CLAUDE_PLUGIN_DATA}` for an installed plugin, a temp directory if neither is writable; `KB_INDEX=DIR` elsewhere, `KB_INDEX=0` in memory only), is never committed, and is rebuilt (a few seconds) the first time after any kb file changes; a cold `pack` then takes about 0.1 s.
- **What search sees.** `search` ranks every line (facts, prose paragraphs, code blocks, data rows) the way `pack` does, at most 2 hits per file. It skips the root index files (`README.md`, `_answers.md`, `_gaps.md`, `_conflicts.md`, `_coverage.csv`) and the `_self/` docs; `--index` includes them. The pack never sees them. `--json` gives machine output: each hit carries `path`, `line`, `heading`, `text` and the source ids it cites, and with `-u` also `urls`.
- **The `kb:` hook.** `kb: <question>` is answered from the pack without calling the model when coverage is `good` with no `check:` line; otherwise the prompt goes to the model with the pack attached. `kb+: <question>` always goes to the model with the pack.
- **`kb_ask.py` routing.** Counts and "who cites" questions go to `audit`/`src` (no model). Numbered parts or several questions are split, one pack each (up to 6). `good` goes to Haiku with the packs and no tools (`claude -p` without user plugins and MCP servers), which replies `INSUFFICIENT: ...` when the facts are only related, escalating. `weak`/`none` goes to Sonnet at low effort with the kb and docs servers only.
- **fetch.** `--diff` exits 0 when nothing changed, 1 when a source changed and 2 when a fetch or the selection failed, as `diff` does. `--max-lines N` caps each diff, `--no-save` compares without moving the baseline, `--delay` sets the per-host pause (default 1.1 s). HTML is reduced to its main text first, so page chrome does not count as a change. Only pinned urls carry `artifact_sha256` (raw files at a commit or tag, release downloads); for live pages the hash taken at retrieval sits in `version_or_date`.
